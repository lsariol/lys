# v0.0.0: work not to forget

Things that must be done before v0.0.0 ships but don't have a home in the
code yet. Remove an entry when it's done.

## Twitch: handle every EventSub message

`ConsumeEvent` (`internal/adapters/twitch/eventsub/eventsub.go`) only prints
most cases. Each needs real handling:

- `session_welcome`: `handleSessionWelcome` is empty.
- `session_keepalive`: no timer. If no message arrives within the session's
  `keepalive_timeout_seconds`, the connection is dead and should reconnect.
- `revocation`: Twitch sends it once, then stops sending that channel's
  events. Today it only prints.
  - `authorization_revoked`: the broadcaster removed the bot's permission.
    Stop sending to the channel, set its connection's `authorized` to false
    with an `authorization_revoked` event (a small `connections` method), and
    turn it back on when they re-authorize (`Enroll` does that).
  - `user_removed`: the channel no longer exists (banned or deleted). Mark
    it removed and stop sending to it.
  - `version_removed`: the subscription type or version is gone. Log an
    error that names the type, so the code gets updated.
- `notification` with an unknown subscription type: only printed.
- Unknown `message_type` (the `default` case): silently ignored. Log it.

The chat side has the matching gap: after a 401 that a new app token doesn't
fix, or a 403, the bot keeps trying that channel on every command. Pause
the channel, the same as `authorization_revoked`. Twitch's 429 (rate
limited) isn't handled either.

## Channels: join and leave without a restart

Today the Twitch adapter reads its channel list once, at startup, so
`lys channel add`, `block` and `unblock` (and a revoked grant) only take
effect after `docker restart lys`. Every way a channel changes should take
effect within seconds:

- Generic, so a new adapter gets it for free: adapters re-read
  `core.Directory` when told the list changed, then join what's new and leave
  what's gone or blocked (Twitch: subscribe or delete the EventSub
  subscription).
- The signal: Postgres `LISTEN`/`NOTIFY` from the `connections` store's
  transactions reaches the running bot even when the change came from the
  CLI in another process. A slow periodic re-read (every few minutes) is the
  safety net.
- Then drop the "after a restart" wording from the CLI and the new-channel
  guide.
- Fits with the sources work (Phase 5) or the website enrollment below,
  whichever comes first.

## Channel owners: join automatically after signing up on the website

When a channel owner signs in on lys.mobasity.com and grants the bot its
permissions, Lys should join their channel without a restart or a manual
step. That needs an endpoint the website calls once the grant succeeds.

- Likely a source: the website reports "channel connected", and Lys creates
  the connection (`connections.Enroll`, as `lys channel add` does) and has
  the Twitch adapter subscribe to the channel's chat without a restart (today
  it only joins at startup). Revisit when the sources work starts.
- The endpoint must be authenticated, like the notification inlet (Phase 2).
- It's the reverse of `authorization_revoked` above. A channel that
  re-authorizes after a revoke comes back through the same path.
- Starting point: the unmerged draft on
  `feature/Add-Twitch-Enrollment-Support` (enrollment, a thread-safe channel
  list, API handlers).
